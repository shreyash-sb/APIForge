## Remaining observations and blockers

- Agent planning and several AI-labeled features use deterministic rules/templates, not a live LLM. See `APIForge_AI_Evaluation.md`.
- Mock route configuration is held in a process-local in-memory map; the existing seed routes and any legacy route without `ownerUserId` are excluded from all authenticated management responses and cannot be updated/deleted. There is no mock-route database migration because no persistent mock-route model exists. Public `/api/mock/serve/*` still dispatches all enabled routes by design; route response bodies remain publicly retrievable when the endpoint path/method is known. Do not put secrets in served mock data. Same-path/method collisions remain a shared public-namespace limitation.
- Outbound safe mode defaults on for production or when explicitly set via `OUTBOUND_REQUEST_SAFE_MODE=true`; it remains off by default in development. Enable it for any demo reachable by untrusted users. Local UI fixtures that intentionally call loopback mocks should run in an isolated test environment with that restriction disabled.
- The previous QA session exposed a development Gemini credential in diagnostic output. Rotate it before any live-provider call. The credential value is not recorded here.
- OpenAPI import/test generation, reports/export, responsive breakpoints, SSE UI behavior, live Gemini behavior, and explicit browser confirmation-dialog acceptance remain incomplete or unexecuted. Mock creation/execution/log display passed in the browser; see the manual checklist for evidence.

### AUTHZ-02 remediation — 2026-10-27

- Reproduced the prior defect before editing: synthetic A created a route (HTTP 201); synthetic B requested `GET /api/mock/routes` (HTTP 200) and the response contained A's route ID (`bSeesA=true`). This was an isolated ephemeral loopback Express app using the actual auth and mock routers.
- Selected policy: private management configuration is owner-scoped using the authenticated backend identity. Missing-owner legacy/default records are hidden and immutable through management; they remain available to the intentionally public mock-serving dispatcher for compatibility. `generate-from-spec` creates owned routes, and overwrite affects only the requesting user's routes. Request logs are filtered and cleared by matched route owner; unmatched/legacy logs are not returned to any account.
- Files changed: backend mock route type/service/controller/router and agent tool integration; mock-server unit and HTTP integration tests. The router factory accepts an isolated service for tests; production still mounts the existing default service.
- Verification: `node --import tsx --test test/mockServer.test.ts test/mockServerHttpIntegration.test.ts test/auth.test.ts test/authController.test.ts` — **43 passed, 0 failed, 0 skipped**. Backend TypeScript build passed. Backend lint exited 0 with 39 existing warnings and no errors.
- Actual HTTP regression assertions: A can create/list/read/update/delete its route; B's list omits it and B receives indistinguishable 404s for guessed-ID read/update/delete; B can create/list/update/delete its own route; an owner ID submitted in JSON is ignored; anonymous management gets 401; ownerless seed management gets 404; public unauthenticated seed serving remains 200. User B cannot see or clear A's request logs. An overwrite-generation unit case confirms user A's generation does not delete user B's route.
- There is no persisted mock-route collection in the inspected backend; current route ownership is runtime-only and routes reset with the process. If persistence is added, ownerUserId must be mandatory for new records and ownerless legacy documents must remain quarantined from management pending an explicit migration.
- Browser UAT has not been rerun. Public serving is intentionally unauthenticated and continues to reveal configured response bodies to callers that know the public path/method; this is not covered by the management isolation claim. Demo readiness remains **INCONCLUSIVE DUE TO BLOCKERS** because browser workflows, live AI, SSE, reports/export and responsive UI remain incomplete.
